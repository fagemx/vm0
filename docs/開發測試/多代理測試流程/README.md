# 多代理測試補完流程

## 目標

用平行派發的方式，高效為 vm0 缺測試的 API routes 補上 integration tests。

## 檔案結構

```
多代理測試流程/
├── README.md              ← 本檔（總覽）
├── 流程設計.md            ← 三階段流程 + 設計決策
├── briefing.md            ← 給 agent 的任務簡報（共用知識）
├── 執行紀錄.md            ← 每次執行的結果和改進
├── 已知陷阱.md            ← 踩過的坑，避免重複犯錯
└── agent-teams-調查.md    ← Agent Teams 可行性調查與實踐計畫
```

## 兩套方案

| 方案 | 狀態 | 適合場景 |
|------|------|---------|
| **A: briefing + Task tool** | 設計完成，待實戰 | 獨立任務、手動組裝 |
| **B: Agent Teams** | 調查完成，待驗證 | 需互相溝通的複雜任務 |

## 快速開始（方案 A）

1. 讀 `流程設計.md` 了解三階段流程
2. 選擇要測試的 routes（參考 `../貢獻策略調查-2026-02-07.md` 第四節）
3. 把 `briefing.md` 餵給每個 agent
4. 收集產出 → 組裝 → 驗證 → 提交

## 快速開始（方案 B）

1. 讀 `agent-teams-調查.md` 了解可行性和限制
2. 按實踐計畫的 4 個階段逐步驗證
3. 跟方案 A 對比效率後決定主力方案
