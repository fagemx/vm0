# 流程設計

## 三階段架構

```
Phase 0: 準備 ──→ Phase 1: 平行派發 ──→ Phase 2: 組裝驗證提交
 （做一次）        （每 route 一個 agent）    （我來做）
```

---

## Phase 0: 準備 Briefing

**做一次，之後複用。每次有新發現就更新。**

輸入：
- 目標 route 列表（從貢獻策略調查中挑選）
- 現有 api-test-helpers.ts 的函數清單
- 現有測試範例（作為模板）

輸出：
- `briefing.md`（給 agent 的完整任務說明）

---

## Phase 1: 平行研究 + 撰寫

**每個 route 派一個 agent（用 Task tool, run_in_background=true）**

### Agent 收到的指令模板

```
你的任務：為 {route_path} 撰寫 integration tests。

## 必讀
1. 先讀 briefing.md（測試慣例和已知陷阱）
2. 讀目標 route.ts 理解所有分支
3. 讀相關 schema 檔

## 產出格式
請產出以下兩個區塊：

### 區塊 1: 測試檔完整內容
路徑: {test_file_path}
（完整可用的 .test.ts 內容）

### 區塊 2: 需要的新 Helper（如果有）
（函數定義 + import 需求，我會統一合併進 api-test-helpers.ts）
如果不需要新 helper，寫「無需新 helper」。
```

### 平行上限

建議一次派 3 個 agent：
- 超過 3 個容易超出 context 管理能力
- 3 個的產出量已經足夠一個 PR

---

## Phase 2: 組裝 + 驗證 + 提交

### 2a. 收集產出
- 讀取每個 agent 的 output
- 檢查產出品質（格式是否正確、import 路徑是否對）

### 2b. 合併共用檔案
- 把所有 agent 需要的新 helper 合併進 api-test-helpers.ts
- 去重（多個 agent 可能需要相同 helper）
- 確保 import 不重複

### 2c. 寫入檔案
- Write 每個測試檔
- Edit api-test-helpers.ts

### 2d. 驗證
```bash
cd /home/ubuntu/vm0/turbo

# 1. Format
pnpm format

# 2. Lint
pnpm turbo run lint --filter=web

# 3. Type check
pnpm turbo run check-types --filter=web

# 4. Test（只跑新增的測試）
DATABASE_URL=postgresql://ubuntu:vm0dev@localhost:5432/vm0_dev \
pnpm vitest run {test_file_1} {test_file_2} {test_file_3}
```

### 2e. 修問題
- type error → 修型別
- test failure → 分析失敗原因，修測試或記錄到已知陷阱

### 2f. 提交
```bash
# 一個 PR 包多個 route 測試
git checkout -b test/batch-api-route-tests
git add {所有新增/修改的檔案}
git commit -m "test(web): add integration tests for {route1}, {route2}, {route3}"
git push origin test/batch-api-route-tests
gh pr create --repo vm0-ai/vm0 ...
```

## 設計決策

### 為什麼不讓 agent 直接寫入檔案？

- api-test-helpers.ts 是共用的，平行寫會衝突
- agent 可能犯格式錯誤，統一組裝可以品質把關
- 驗證步驟需要完整 context（所有檔案都到位才能跑 type-check）

### 為什麼一個 PR 包多個 route？

- 減少 PR 開銷（review、CI 等待、merge 衝突）
- 相關 route 的測試放一起更有邏輯（如整個 cli/auth flow）
- 每天目標：2-3 個 PR，每個包 2-4 個 route

### Briefing 為什麼獨立成檔？

- Agent 不會主動讀 .claude/skills/
- 每次對話的 context 是新的，不能假設 agent 記得上次
- Briefing 就是 agent 的「記憶替代品」
