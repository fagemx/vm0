# 已知陷阱

每次踩坑就更新這裡。Briefing 會引用此檔。

---

## 環境類

### 1. DATABASE_URL 必須手動傳
- **問題**：`pnpm vitest run` 不會自動有 DATABASE_URL
- **解法**：跑測試時加上 `DATABASE_URL=postgresql://ubuntu:vm0dev@localhost:5432/vm0_dev`
- **發現於**：PR #2508 首次執行測試全部 500 error

### 2. @vm0/core 首次 build
- **問題**：`check-types` 會因為 core 的 `./dist/bundled` 不存在而失敗
- **解法**：重跑一次即可（turbo 會 cache build 結果）
- **發現於**：PR #2508 type-check 第一次失敗

## 測試撰寫類

### 3. vi.mock 清單要完整
- **問題**：缺少 mock 會導致真實模組被載入，引發奇怪錯誤
- **必要 mocks**（幾乎所有 web route 測試都需要）：
  ```typescript
  vi.mock("@clerk/nextjs/server");
  vi.mock("@e2b/code-interpreter");
  vi.mock("@aws-sdk/client-s3");
  vi.mock("@aws-sdk/s3-request-presigner");
  vi.mock("@axiomhq/js");
  ```
- **發現於**：觀察現有測試的共同模式

### 4. ESLint 禁止測試檔直接用 globalThis.services.db
- **問題**：Ethan 加了 `web/no-direct-db-in-tests` eslint 規則
- **解法**：所有 DB 操作都要透過 api-test-helpers.ts 的 helper 函數
- **發現於**：PR #2508 設計時

### 5. non-null assertion (!) 要注意型別
- **問題**：`token!.userId` 需要確保 token 的型別包含 userId
- **解法**：helper 函數的 return type 要明確定義
- **發現於**：PR #2508 type-check

## Git / PR 類

### 6. 工作目錄是 turbo/ 不是 repo root
- **問題**：git add 路徑需要從 repo root 算起，但 cwd 常在 turbo/
- **解法**：用相對路徑 `apps/web/...` 或注意 cwd
- **發現於**：PR #2508 commit 時 pathspec 錯誤

### 7. .gitignore 在 personal/notes 分支會擋筆記
- **問題**：`git add` 筆記目錄時被 .gitignore 擋住
- **解法**：用 `git add -f` 強制加入
- **發現於**：推送筆記時

### 8. git rebase --continue 不支援 --no-edit
- **問題**：`--no-edit` 不是 git rebase 的有效選項
- **解法**：直接 `git rebase --continue` 不加 flag
- **發現於**：PR #2508 rebase 時
