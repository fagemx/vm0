# 遺漏事件紀錄：PR #2512 canonical 測試 (2026-02-07)

## 事件摘要
- PR #2512 新增 `alternates.canonical`（site + web 的 blog list / blog post `generateMetadata`）
- Reviewer (e7h4n) 要求補自動化測試
- PR 提交時未附帶測試，被 request changes

## 遺漏原因
- 改動的是 `page.tsx` 的 `generateMetadata`，屬於 **page-level** 行為
- `docs/testing/web-testing.md` 存在但只涵蓋 **API route**（`route.test.ts`），不涵蓋 page-level 測試
- 我們的 `briefing.md` 同樣只涵蓋 API route 測試模式
- page-level 的 `generateMetadata` 測試需要完全不同的 mock 策略（`next-intl/*`, `@clerk/nextjs`, `next/navigation`），沒有既有規範可參考

## 影響
- PR 被 request changes，增加往返時間
- 需要新增 `__tests__/page.test.ts`（非 `route.test.ts`）驗證 canonical URL

## 修復方式
新增 2 個測試檔，共 5 個測試：
- `app/[locale]/blog/__tests__/page.test.ts` — blog list canonical URL（2 tests）
- `app/[locale]/blog/posts/[slug]/__tests__/page.test.ts` — blog post canonical URL（3 tests）

測試模式與 API route 測試不同：
- 不使用 `testContext()` / `createTestRequest()`
- 用 `vi.hoisted()` 設定 `NEXT_PUBLIC_BASE_URL` 環境變數
- Mock 外部套件：`next-intl/*`, `@clerk/nextjs`, `next/navigation`
- 用 MSW mock Strapi API（blog post 的 `getPost` 呼叫）

## 教訓
1. **API route ≠ page**：`briefing.md` 只涵蓋 `route.ts` 測試，`page.tsx` 的 `generateMetadata` 是不同類別，需要不同的 mock 策略
2. **任何行為改動都需要測試**：不論是 API route 還是 page metadata，只要改了可觀察行為就應補測試
3. **文件盲區要主動補**：發現既有文件沒覆蓋的測試場景時，應建立新的測試模式文件
