## 📋 VM0 貢獻準備工作完整摘要

### 1️⃣ 貢獻規範重點

#### 開發環境
- 使用 **Dev Containers** 開發（推薦 OrbStack/Docker + VS Code）
- SSL 憑證需用 **mkcert** 在主機上生成
- 社區貢獻者需手動配置 `.env.local`（Clerk, E2B, R2 keys）

#### PR 流程
```
Fork → 建立分支 → 修改 → Commit → Push → 建立 PR
```

#### Commit 格式 (Conventional Commits)
```
<type>[scope]: <description>
```

| 規則 | 說明 |
|------|------|
| Type 小寫 | `feat:`, `fix:`, `docs:` |
| Description 小寫開頭 | `add new feature` 不是 `Add new feature` |
| 無句號 | 結尾不加 `.` |
| 標題 < 100 字元 | 保持簡潔 |
| 祈使語氣 | `add` 不是 `added` |

**常用 types**: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `ci`, `perf`

### 2️⃣ 代碼風格要求（零容忍）

| 項目 | 規則 |
|------|------|
| **TypeScript** | ❌ 禁止 `any`，使用 `unknown` + 類型收窄 |
| **Lint 抑制** | ❌ 禁止 `eslint-disable`, `@ts-ignore`, `@ts-nocheck` |
| **動態 import** | ❌ 禁止 `await import()`，用靜態 import |
| **硬編碼 URL** | ❌ 禁止，用 `env()` 取得配置 |
| **Fallback 模式** | ❌ 禁止靜默 fallback，應 **fail fast** |
| **錯誤處理** | 不要過度包裝 try/catch，讓錯誤自然傳播 |

#### 命名規範 (ESLint 強制)
```typescript
// 變數、參數: camelCase, UPPER_CASE, PascalCase
const userName = "alice";
const MAX_RETRIES = 3;
const UserComponent = () => {};

// 函數: camelCase 或 PascalCase (React 組件)
function getUserById() {}
function MyComponent() {}

// 類型: PascalCase
interface UserData {}
type ApiResponse = {};
```

### 3️⃣ 測試哲學

> **"Write tests. Not too many. Mostly integration."** — Kent C. Dodds

| 類型 | 用途 | 備註 |
|------|------|------|
| **Integration** | ✅ 主要測試 | 測試入口點（CLI 命令、API 路由） |
| **E2E** | ⚡ 僅 happy path | 慢且昂貴，只驗證系統整合 |
| **Unit** | ❌ 不寫 | 整合測試已覆蓋內部邏輯 |

#### Mock 邊界規則
```typescript
// ✅ Good: Mock 外部依賴
vi.mock("@clerk/nextjs");
vi.mock("@aws-sdk/client-s3");

// ❌ Bad: Mock 內部代碼（路徑以 ../ 開頭）
vi.mock("../../lib/user-service"); // 錯誤！
```

- **用真實 DB**（Docker PostgreSQL）
- **用真實檔案系統**（temp dir）
- **用 MSW mock HTTP**（不直接 mock fetch）
